weeboweebo started as a browser chat app so my family could reach my sisters after their school banned phones. This is that project grown up, and renamed. I rebuilt it into FlatFold, an end-to-end encrypted messenger that runs in a browser or as an installed app and is built so the server knows as little about you as it possibly can. Messages are encrypted on your own device with the real Signal machinery, X3DH to open a conversation and a double ratchet to keep it going, all sitting on audited crypto primitives instead of anything I hand-rolled. The server is a Cloudflare Worker with a Durable Object mailbox for each person, and it only ever holds ciphertext, only while you're offline, and it throws that away the moment your other device says the message landed. No message history, no contact lists, no read receipts, no IP logs. The name is an origami term for a crease pattern that folds completely flat, which is about how flat I wanted the server's memory of you to be.

The part I sank the most time into isn't a feature you can point at. There's a transparency page that lists every single field the database stores and says plainly what a subpoena could pull out of it, and a test fails the build if that page ever drifts from the real schema, so it can't quietly start lying. I went down a long hole on sealed sender too, which hides who you're talking to on top of what you're saying, and that meant routing sends through an independent relay run by a different company, so no single party ever sees both your address and your message. And where a messenger that lives in a browser is weaker than a real installed app, because the same server that carries your messages also hands you the code that reads them, I wrote that down on the page instead of hiding it. If I'm going to ask people to trust it, the honest move is to be specific about how far that trust should actually go.

It has since stopped being only a browser tab. There are installed apps now for iPhone, iPad and Mac, built from the same React code through Capacitor, and they exist mostly to close the gap I had just finished admitting to, because an app you installed once was checked once, where a web page gets handed to you fresh by the server on every single load. Most of the work turned out to be the places where a WebView quietly isn't a browser. A Mac won't expose a microphone to one at all, so voice notes there are recorded and played by Swift I had to write myself, and the app pins the connection to my own public keys, which I only believed after shipping a deliberately wrong pin first and watching it refuse to connect, since a pin that matches everything also lets the app work perfectly.

The other half was making an account survivable without making the server worth attacking. The password is still the key and there is still no reset, so instead there are recovery codes you keep, an authenticator app if you want a second factor, and a change-password path that re-wraps everything and can't be interrupted into a half-broken state. A reload used to always ask for that password again, because the key derived from it lives only in memory and is never written anywhere a script or an extension could read it. That part hasn't changed, but Face ID on a phone or a passkey in a browser can now unwrap it instead of you retyping. The passkey isn't a doorman that checks you and then hands over a key that was sitting there readable anyway, which is the easy version and the one I threw out; the key is genuinely wrapped by a secret that never leaves the authenticator. And every notification the app can produce says "New activity" and nothing else, no sender and no message text, because a lock-screen banner reading "Alice: hey" would quietly undo the whole thing.
